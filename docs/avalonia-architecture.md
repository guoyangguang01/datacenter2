# SDNCustom Avalonia/.NET 架构

## 进程边界

- 服务端是一个 Generic Host，可显示 Avalonia 管理界面或以 `--headless` 运行。
- 每个客户端只保存并运行一个设备连接；连接参数属于客户端，点表由服务端“用户管理”维护，
  客户端接收后在本地缓存并只读展示。
- 设备协议只在客户端进程执行。服务端不再持有设备连接。

## gRPC 流

客户端启动后连接 `AgentGateway.Connect` 双向流。首条消息是 `Hello`，包含客户端代码、
客户端名称、协议类型、显示用 Endpoint、应用版本和完整点表目录。

服务端只允许预登记的客户端代码。重复在线代码会被拒绝，原会话保持不变。

## 数据路径

```text
第三方数据
  ↓ 客户端 200ms 采集 INPUT
客户端 ChangeGate（死区/质量）
  ↓ gRPC PointBatch
服务端最新值 + InfluxDB
  ├─ Avalonia 数据视图
  └─ INPUT→多个 OUTPUT 路由
       ↓ gRPC WritePoint
     各集成客户端写入目标设备/程序
       ↓ WriteResult
     服务端记录 OUTPUT 意图值
```

OUTPUT 不参与读取采集，因此传播值不会回流形成自触发循环。

## 断线语义

- gRPC 流关闭或心跳失败时，客户端立即停止设备通讯。
- 不写本地缓存，不补传离线期间的数据。
- 客户端按 2 秒起步、倍增、封顶 60 秒重连服务端。
- 服务端在 SQLite 中保存期望运行状态；重连成功且期望状态为运行时，客户端自动恢复设备通讯。

## 存储

- SQLite：业务系统、客户端系统白名单、INPUT 端点、统一 PointLink 输入/输出关系、
  期望运行状态和最新值。
- InfluxDB：`point_value` measurement；标签为 `client_code`、`point_id`、`direction`，字段按数据类型区分。

## 身份边界

当前按需求只使用 `clientCode` 作为身份，不提供人类账号、密码或客户端证书。
默认按可信内网部署，使用非 TLS 连接；需要加密链路时可在服务端与客户端配置中启用 TLS。

## 界面参考映射

- 服务端主窗口采用参考程序的顶部大图标 Ribbon、左侧系统监视器、中央数据视图/模拟/历史标签、
  底部日志与通讯状态布局。
- 服务端“用户管理”提供客户端系统、点表增删和 CSV 导入导出；“系统设置”展示 gRPC、TLS、
  SQLite 和 InfluxDB 配置边界。
- 客户端主窗口采用数据中心设置、数据用户设置、实时通讯设置三段布局，中央并排显示
  INPUT/OUTPUT 实时值、质量和更新时间，底部仅显示运行日志。
- 客户端应用服务端下发的点表，但界面不展示点表配置，也不提供点表增删改或 CSV/JSON 导入导出。
- 客户端“详细设置”仅配置中心发往用户、用户发往中心的频率、缺项和变化发送策略。
- 参考截图位于 `img/`，只用于布局和交互对照，不复制参考程序的专有图片、图标或二进制资源。
